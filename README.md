# PorousFlow 2D

Рабочий проект метода конечных объёмов для двухфазного вытеснения несжимаемых
жидкостей в пористой среде на ячейке пятиточечной системы.

## Реализовано

- прямоугольная область с четвертями скважин, вырезанными в противоположных
  вершинах;
- две постановки: конечные скважинные изобары на гидродинамической сетке и
  точечные четверти скважин на равномерной прямоугольной сетке;
- скалярная, диагональная и полная симметричная абсолютная проницаемость;
- постоянные свойства, прямоугольные зоны и поля на регулярной сетке из NPZ;
- степенные относительные фазовые проницаемости;
- решение давления методом CG с предобуславливателем PyAMG;
- повторное использование структуры матрицы давления и иерархии AMG между
  временными шагами без замораживания текущих коэффициентов;
- переключаемые схемы переноса: адаптивная неявная Backward Euler и явная
  IMPES/CFL; обе используют консервативные upwind-потоки;
- необязательное последовательное ускорение неявного переноса с помощью Numba;
- контроль физического диапазона насыщенности и баланса фаз;
- командный интерфейс и настольный интерфейс с постпроцессингом;
- сохранение полей давления и водонасыщенности, скважинных функций и служебных
  данных в NPZ/HDF5, а истории скважин — дополнительно в CSV.

Математическая постановка и принятые проектные решения находятся в
[`docs/PROJECT_DESIGN.md`](docs/PROJECT_DESIGN.md).

## Установка

Рекомендуется Python 3.12 (поддерживаются 3.11–3.13; Python 3.14 пока не
используется из-за совместимости готовых пакетов PyAMG/Numba). Минимальная
установка включает NumPy, SciPy и PyAMG:

```powershell
python -m pip install -e .
```

Для дополнительного ускорения неявного переноса установите Numba:

```powershell
python -m pip install -e ".[jit]"
```

Режим Numba в этой версии последовательный: распараллеливание расчёта не
включено. В приложении можно выбрать `Автоматически`, `Numba` или
`Без Numba`. Автоматический режим использует Numba, если пакет установлен, и
иначе выполняет тот же алгоритм на Python.

Для YAML и HDF5:

```powershell
python -m pip install -e ".[yaml,hdf5]"
```

JSON поддерживается без дополнительных пакетов. Готовый небольшой пример:
`examples/five_spot.json`.

## Запуск

Проверить вход, построить сетку и вывести показатели качества:

```powershell
porous-fvm validate examples/five_spot.json
```

Сохранить сетку:

```powershell
porous-fvm mesh examples/five_spot.json -o mesh.npz
```

Выполнить расчёт:

```powershell
porous-fvm run examples/five_spot.json -o results.npz
```

По умолчанию каждый запуск получает собственную папку
`results/<имя>-<постановка>-<статус>-<дата-время>/`. В ней создаются:

- `input.json` — копия входного проекта, с которым выполнен расчёт;
- `result.npz` (либо HDF5 при явном выборе) — сетка, свойства среды, все сохранённые поля
  `pressure[time,i,j]` и `water_saturation[time,i,j]`, гранные расходы и
  скважинные временные ряды;
- `result.wells.xlsx` — книга Excel с исходными временными рядами, дебитами
  жидкости, воды и нефти, обводнённостью, накопленными объёмами, диагностикой
  расчёта и готовыми редактируемыми графиками;
- `result.summary.json` — краткая сводка конечного состояния.

Основные итоговые функции имеют имена `producer_liquid_rate(t)` и
`producer_water_cut(t)`, где
`producer_water_cut = producer_water_rate / producer_liquid_rate`.

Открыть настольный интерфейс:

```powershell
py -m porous_fvm.gui
```

### Единицы конечного времени

На вкладке `5 Расчёт` конечное время можно вводить в секундах (`с`), часах
(`ч`) или сутках (`сут`). При переключении единицы уже введённое физическое
время сохраняется: например, `2 сут` превращаются в `48 ч`. Во входном JSON и
внутри решателя время по-прежнему хранится в секундах (`end_s`), поэтому эта
настройка не меняет математическую модель и не нарушает совместимость старых
проектов. Максимальный шаг и интервал кадров остаются в секундах, поскольку
обычно они существенно меньше суток.

### Сборка Windows без передачи исходных файлов

Для подготовки передаваемой версии сначала установите инструменты сборки:

```powershell
py -m pip install -e ".[distribution]"
```

Затем из корня проекта выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\build_windows.ps1
```

Сценарий создаёт автономный каталог `release\PorousFlow2D`. Получателю нужно передать
этот каталог целиком; Python и файлы `.py` ему не требуются. Numba и PyAMG
входят в сборку и продолжают использоваться при расчёте. Сначала следует
проверять именно такую папочную сборку. После её проверки можно получить один
исполняемый файл командой:

```powershell
powershell -ExecutionPolicy Bypass -File .\build_windows.ps1 -OneFile
```

Однофайловая версия удобнее для передачи, но запускается через временную
распаковку и сложнее диагностируется. Компиляция скрывает исходные файлы от
обычного пользователя, однако не является абсолютной защитой от специально
выполненного обратного анализа.

### Изменение области и сетки в приложении

Над вкладками находится отдельный блок `Постановка задачи`. В нём доступны:

- `Гидродинамическая сетка` — расчётная область ограничена конечными изобарами
  скважин, а сетка следует линиям тока и изобарам;
- `Равномерная сетка, точечные скважины` — другая расчётная область: полный
  прямоугольник с равномерной декартовой сеткой и непроницаемыми внешними
  сторонами. Нагнетательная и добывающая скважины находятся соответственно в
  нижней левой и верхней правой угловых ячейках. Каждая представляет четверть
  скважины.

После выбора постановки справа доступны пять последовательных вкладок:

- `1 Область`: размеры по X и Y, толщина пласта и радиусы обеих скважин;
- `2 Сетка`: число ячеек вдоль и поперёк потока и способ построения.
  `Гладкая (не φ–ψ)` использует трансфинитную интерполяцию точных круговых
  границ. Режим `ТФКП: точечный источник–сток` использует аналитический
  комплексный потенциал периодической пятиточечной системы. Границей каждой
  скважины служит первая изобара, которая касается окружности заданного
  радиуса и нигде не заходит внутрь неё. Уровни потенциала равномерны, поэтому
  физические размеры ячеек естественно изменяются по логарифмическому закону:
  мелкие ячейки находятся у источника и стока, крупные — в центре. Линии тока
  равномерны по функции тока, дополнительное сгущение у внешних границ не
  применяется. Поля дополнительного сгущения в этом режиме заблокированы.
  `Мин. угол ячейки` задаёт только порог
  отбраковки сетки;
- `3 Модель`: имя проекта, проницаемость, пористость, плотности и вязкости
  воды и нефти, а также начальная водонасыщенность. Для нового проекта можно
  задать однородную изотропную проницаемость и постоянную пористость. При
  загрузке проекта с зонами или внешними полями можно сохранить эти поля без
  преобразования в одно постоянное значение;
- `4 ОФП и скважины`: связанная вода, остаточная нефть, концевые значения и
  показатели степенных ОФП, давления нагнетательной и добывающей скважин и
  доля воды в закачиваемой жидкости. Для равномерной постановки здесь же
  выбирается исходный индекс Писмена или угловая поправка Маскета;
- `5 Расчёт`: начальное и конечное время (для конечного доступны секунды, часы
  и сутки), максимальный временной шаг, интервал
  сохранения кадров, выбор явного или неявного переноса, целевой CFL для явной
  схемы, максимальное изменение насыщенности для неявной схемы, допуски и
  максимальное число итераций решателей давления и насыщенности. Поле
  `Ускорение переноса` управляет необязательной Numba-компиляцией; оно не
  изменяет математическую схему.

В JSON этот выбор задаётся в блоке `numerics.transport`:

```json
"acceleration": "auto"
```

Допустимые значения: `auto`, `numba`, `python`. Порядок обхода ячеек
кэшируется между шагами, но перед каждым использованием проверяется по
актуальным направлениям потоков. Если направления изменились, порядок
строится заново. Структура разреженной матрицы давления также создаётся один
раз, однако её численные коэффициенты обновляются на каждом шаге по текущей
подвижности фаз. Поэтому обе оптимизации не снижают точность решения.

`Показать область` сразу перерисовывает контур без запуска решателя.
`Построить сетку` заново строит гладкую структурную сетку, точно следующую
границам области и четвертям скважин; качество ячеек проверяется до расчёта.
Аналитическая сетка предполагает однородную изотропную среду. Для неоднородной
или анизотропной проницаемости она остаётся допустимой body-fitted сеткой, но
её линии уже не совпадают с фактическими линиями тока.

Имя генератора в JSON — `point_source_isobars`. Старые имена
`conformal_laplace` и `schwarzian_conformal` при загрузке автоматически
переводятся на новый алгоритм.

Для равномерной постановки имя генератора — `uniform_cartesian`, а тип геометрии
— `five_spot_point_wells`. Готовый пример находится в
`examples/five_spot_uniform.json`.

### Аналитический приток к угловой четверти скважины

В равномерной постановке радиус скважины не вырезается из области. Для угловой
ячейки используется модель давления на забое

```text
q = WI · (p_w - p_cell),
WI = (π/2) h sqrt(kx ky) λ_t / [ln(r_e/r_w) + s].
```

Множитель `π/2` соответствует сектору в 90°, то есть ровно четверти полной
скважины. Эквивалентный радиус `r_e` вычисляется по формуле Писмена после
зеркального отражения угловой ячейки относительно двух непроницаемых сторон:
исходная ячейка `Δx × Δy` превращается в центральную ячейку
`2Δx × 2Δy`. Для изотропной квадратной сетки получается
`r_e = 0.28 sqrt(2) Δ ≈ 0.396 Δ`. Поэтому необходимо `r_w < r_e`.

Для нагнетателя источник жидкости положителен, для добывающей скважины —
отрицателен. Эти члены входят непосредственно в балансы двух угловых ячеек;
на внешних гранях поток остаётся нулевым. Формула поддерживает изотропную либо
диагональную анизотропную проницаемость, оси которой совпадают с осями сетки.

По умолчанию пример равномерной пятиточки использует поправку Маскета:

```json
"well_model": {"corner_correction": "muskat"}
```

Сначала решается линейная задача с исходными индексами Писмена. Разность между
её полным сопротивлением и сопротивлением по формуле Маскета

```text
Q_M = (π k h λ_t / 4) Δp / [ln(sqrt(2) L / r_w) - 0.6188]
```

делится поровну между двумя симметричными скважинами и переводится в
дополнительный безразмерный угловой скин. Этот скин фиксируется на весь
двухфазный расчёт; дебит на последующих шагах не подгоняется. Режим требует
квадратной области, одинаковых радиусов скважин и однородной изотропной
проницаемости. Для воспроизведения исходной модели задайте
`"corner_correction": "none"`.

Расчёты не перезаписывают друг друга: даже два запуска в одну секунду получают
разные каталоги. В имени каталога указана постановка `hydrodynamic` или
`uniform`, поэтому результаты двух способов дискретизации не смешиваются.

Кнопка `Новый…` создаёт в памяти новый проект с безопасными начальными
значениями. После заполнения вкладок нажмите `Применить параметры`, а затем
`Сохранить как…`: приложение сформирует полный входной JSON, который можно
сразу загрузить или использовать для расчёта. Несохранённый новый проект нельзя
запустить, поэтому результат всегда связан с конкретным входным файлом.

После редактирования любого поля появляется оранжевая надпись
`Есть неприменённые изменения`. Кнопка `Применить параметры` проверяет значения
и запоминает их для следующего построения сетки или расчёта; после этого
индикатор становится зелёным. Эта кнопка не изменяет файл проекта. Чтобы
изменения сохранились после закрытия программы, служит `Сохранить как…`: она
записывает параметры в новый JSON-проект, не перезаписывая исходный файл.

Во время расчёта отдельная строка показывает выполненную долю, прошедшее и
примерное оставшееся время. Кнопка `Остановить` завершает текущий безопасный
временной шаг, сохраняет все полученные поля и скважинные функции в файл
в отдельную папку со словом `partial` и сразу открывает последний промежуточный кадр.
Такой файл можно позднее открыть обычной кнопкой `Открыть результаты…`.

### Просмотр и анимация результатов

После завершения расчёта результат открывается автоматически. Ранее полученный
файл можно загрузить кнопкой `Открыть результаты…`. В списке `Поле`
доступны водонасыщенность, давление и скважинные функции. Для давления и
насыщенности список `Вид` переключает три представления: цветную заливку без
линий сетки, заливку с расчётной сеткой и цветные диапазоны с подписанными
изолиниями. Изолинии строятся в физических координатах криволинейной сетки.
Ползунок выбирает сохранённый
момент времени, а кнопка `▶` воспроизводит кадры поля.

Основной файл результата имеет расширение `.npz` (либо `.h5`/`.hdf5`). Файл
`*.summary.json` содержит только краткую сводку, однако приложение автоматически
найдёт лежащий рядом основной файл результата, если выбрать сводку. Если файл
результата случайно выбран через кнопку загрузки проекта, он также будет
автоматически открыт в просмотрщике, а текущий проект останется выбранным.

В режиме `Скважинные функции` строятся два графика для добывающей скважины:
дебиты жидкости и воды в м³/сут и обводнённость в процентах. Интервал истории
скважин задаётся независимо параметром `output.well_history_every_s`. Например,
значение `3600` записывает дебиты и обводнённость каждый час. Параметр
`time.save_every_s` управляет только кадрами полей. Чтобы не сохранять
промежуточные поля, задайте `output.store_field_frames = false`; в результате
останется лишь конечное состояние, необходимое для целостности файла.

### Анализ сходимости

Сходимость следует проверять отдельно по времени, по сетке и по допускам
линейного/нелинейного решателя. Во всех сериях изменяется только один класс
параметров, остальные параметры и моменты сохранения должны совпадать.

Для временной сходимости неявной схемы рекомендуется последовательно уменьшать
`initial_step_s`, например с 3600 до 1800 и 900 с. Значение
`max_saturation_change = 1` отключает дополнительное дробление уже сошедшегося
неявного шага. При необходимости более строгой контрольной серии можно задать
`max_saturation_change`, например `0.2`, `0.1` и `0.05`, но этот ограничитель
существенно увеличивает время расчёта на мелких прискважинных ячейках.

Для сеточной сходимости одновременно увеличиваются оба числа ячеек с постоянным
отношением сторон, например `24×16`, `36×24`, `54×36`. Сравниваются:

- дебит жидкости и обводнённость в одинаковые моменты времени;
- время прорыва воды при одном фиксированном критерии, например 1 %;
- накопленная добыча воды и нефти;
- интегральная, взвешенная на поровый объём норма различия насыщенности;
- максимальная невязка баланса массы.

Гидродинамическую и равномерную постановки нельзя считать двумя уровнями одной
сеточной последовательности: у них различаются расчётная область и модель
скважины. Сначала проверяется сходимость каждой постановки отдельно, и только
после этого сопоставляются их уже сошедшиеся дебиты, обводнённость и время
прорыва. Метод Ричардсона или GCI имеет смысл применять по трём последовательно
сгущённым сеткам только при монотонном приближении выбранной интегральной
величины.

Без установки команды можно выполнять через модуль, указав каталог исходников
в `PYTHONPATH`.

## Входные поля среды

Проницаемость и пористость задаются в разделе `medium` независимо от расчётной
сетки. Поддерживаются:

- `constant` — одно значение во всей области;
- `zones` — прямоугольные зоны `bounds_m=[xmin,ymin,xmax,ymax]`;
- `spatial_field` — регулярная исходная сетка в NPZ с массивами `x_edges`,
  `y_edges`, `permeability` и `porosity`.

Пространственное поле сначала переносится на вспомогательную сетку для
построения функции тока, затем отдельно — на окончательную сетку.

## Численная схема

Для давления используется двухточечный гранный поток с гармоническим
усреднением нормальной проводимости. На каждом временном шаге полная подвижность
пересчитывается по текущей водонасыщенности. По умолчанию насыщенность решается
неявно методом Backward Euler с Newton–BiCGSTAB и автоматическим уменьшением
шага при плохой сходимости или слишком большом изменении насыщенности. Это
устраняет глобальное ограничение шага объёмом самой маленькой околоскважинной
ячейки. Явная консервативная схема сохранена как опция; для неё шаг по-прежнему
строго ограничивается CFL.

## Проверки

```powershell
$env:PYTHONPATH="src"
python -m unittest discover -s tests -v
```

Тестируются геометрия скважин, положительность ячеек, концевые значения и
монотонность ОФП, баланс полного потока, консервативность шага насыщенности,
скважинные функции и обратная загрузка результата из NPZ.

## Текущие ограничения

- фиксированная ориентация первой версии: нагнетатель в нижней левой, добывающая
  скважина в верхней правой вершине;
- нулевые гравитация и капиллярное давление;
- явный шаг насыщенности может быть малым возле скважинных ячеек;
- для неортогональных сеток пока используется основной двухточечный поток без
  deferred non-orthogonal correction;
- зоны первой версии прямоугольные;
- перестроение сетки во времени и консервативное remapping пока не реализованы.
